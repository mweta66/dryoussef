# إصلاحات عيادة د. يوسف عز الرجال

تم الحفاظ على التصميم الموجود: الألوان واللوجو وصورة الدكتور وأرقام الحجوزات والطوارئ. تغييرات الواجهة وظيفية فقط، مثل رسائل الخطأ وتسميات الوصول ومتابعة الدور برقم الهاتف فقط.

## جرّب الموقع محليًا

من داخل هذا المجلد، باستخدام Node.js 22 أو أحدث:

```sh
npm run demo:seed
npm run demo
```

افتح http://127.0.0.1:4173. بيانات حسابات الدكتور والسكرتارية وأمثلة المتابعة في .demo/guide.txt. كلمات المرور عشوائية ومحلية للاختبار فقط. التهيئة تنشئ بيانات اصطناعية تشمل الفرعين وكل حالات الحجز، وتضيف 20 يوم عمل وملفات حالات وشكاوى وعلاج وتنبيهات وحساب الممرضة. بيانات الدخول في .demo/guide.txt.

إعادة تنفيذ demo:seed تعيد بيانات التجربة إلى حالتها الابتدائية وتغيّر كلمات مرورها . demo:reset يحذف ملفات التجربة الثلاثة فقط. أوقف الخادم قبل إعادة التهيئة أو التصفير. هذه الأدوات لا تقبل هدفًا بعيدًا ولا تتصل بقاعدة الإنتاج.

ملفات .demo خارج public ولا يقدمها الخادم ولا تدخل في النشر. الخادم مربوط بـ 127.0.0.1 فقط. لا ترسل رسائل إلى الأرقام الاصطناعية.

## الفحوص

```sh
npm run check
npm test
```

31 اختبارًا للواجهة والمنطق والصلاحيات والتزامن ورفض التكرار والتعديلات القديمة. فُحص المتصفح مع خادم التجربة الحقيقي، لا مع استجابات وهمية فقط.

لاختبار محاكي قاعدة Firebase، ثبّت اعتماديات functions، وشغّل محاكي RTDB محليًا لمشروع demo-clinic ثم عيّن FIREBASE_DATABASE_EMULATOR_HOST إلى 127.0.0.1:9000 وشغّل:

```sh
npm ci --prefix functions --ignore-scripts
node scripts/emulator-check.cjs
```

أداة الاختبار ترفض أي عنوان ليس localhost/127.0.0.1، وتستخدم مشروع demo-clinic فقط. جرى اختبارها فعليًا بمحاكي RTDB v4.11.2.

## حالة الموقع الفعلي — اقرأ قبل النشر

لم تُعدّل بيانات الإنتاج أو قواعده ولم يتم نشر أي خدمة. public/config.js يبقي secureGateway=false للتوافق مع Firebase الحالي؛ إصلاحات الواجهة تعمل بهذا الوضع، لكن حماية الصلاحيات على السيرفر والتزامن ورمز المتابعة لا تصبح فعالة على الإنتاج إلا بعد نشر الخدمة الآمنة. التجربة المحلية تفعّلها تلقائيًا دون اتصال بالإنتاج.

ملف firebase.secure.json يجمع functions والقواعد وHosting rewrite للخدمة /api/clinic. لا تنشر القواعد المغلقة وحدها على النسخة القديمة.

قبل الانتقال:

1. خذ تصديرًا ونسخة احتياطية من قاعدة البيانات الحالية.
2. جرّب الانتقال على مشروع Firebase تطوير مستقل أولًا. راجع حساب الدكتور والأدوار الموجودة.
3. استخدم أداة التحضير على نسخة محلية من التصدير لإضافة revision ورموز المتابعة والعدادات:

```sh
node scripts/prepare-migration.cjs INPUT.json OUTPUT.json
```

الأداة ترفض استبدال المدخل أو ملف مخرجات موجود، وتتوقف عند بيانات غير صحيحة أو حجز مكرر. لا تنفّذ أي كتابة بعيدة. راجع المخرجات ووزّع رموز المتابعة للحجوزات القائمة قبل تفعيل الحقل.

4. انشر الخدمة وقواعدها على مشروع التطوير، وأضف secureGateway=true في config.js. استخدم firebase.secure.json، وراجع المشروع المستهدف صراحة.
5. اختبر حسابات الطاقم الحقيقية والهاتف ورمز المتابعة، ثم قرر نشر المجموعة معًا على الإنتاج.

تعتمد الخدمة الحالية على معاملات في جذر قاعدة البيانات للحفاظ على شكل البيانات القديم واتساق نقل الحجز بين يومين؛ مناسب لنطاق عيادة، لكن توسع حجم البيانات يستدعي تقسيم التخزين والمعاملات.

سياسة CSP تحتفظ بـ unsafe-inline لمعالجات الأحداث الموجودة حتى لا تتعطل الوظائف. لا يوجد canonical مخترع دون تأكيد عنوان النشر.

مراجع التنفيذ: https://firebase.google.com/docs/database/admin/save-data و https://firebase.google.com/docs/functions/http-events و https://firebase.google.com/docs/rules/unit-tests

## التشغيل من Windows
افتح START-CLINIC.cmd من مجلد العيادة. يشغّل الخدمة المحلية في الخلفية ويفتح http://127.0.0.1:4173. يعيد استخدام الخدمة إن كانت تعمل، ويحافظ على البيانات الموجودة. بعد إعادة تشغيل الكمبيوتر افتح الملف مجددًا. فتح public/index.html مباشرة يعرض تعليمات التشغيل؛ وظائف البيانات تحتاج الخدمة المحلية. بيانات الدخول في .demo/guide.txt. أخطاء التشغيل في .demo/server-error.log.


## التعديلات المدمجة من files.zip
- الممرضة: البحث بالاسم أو الهاتف، قراءة سجل الشكاوى، وإضافة شكوى وعلاج بتاريخ سابق أو اليوم. لا تستطيع تعديل السجل أو حذفه أو قراءة الحجوزات وملاحظات الطبيب الخاصة.
- الطبيب: ملفات الحالات، ملاحظات خاصة، تعديل وحذف الشكاوى، وقائمة التنبيهات مع تعليمها كمقروءة.
- التنبيهات تتحقق كل ثانيتين أثناء فتح الصفحة؛ الصوت يحتاج تفاعلًا أولًا. لا توجد تنبيهات عند إغلاق الصفحة.
- فهرسة المرضى تلقائية عند الحجز، ويمكن تحديثها من إعدادات الطبيب.
- إنشاء حساب الممرضة من المستخدمين، وحذف البيانات التجريبية فقط من الإعدادات.
- حافظنا على الخدمة المحلية وقواعد قاعدة البيانات المغلقة؛ الصلاحيات تنفّذ داخل الخدمة. لم نستبدلها بالقواعد المباشرة في الأرشيف.
- أُلغي رمز المتابعة بالكامل بناءً على الطلب. لا نُشغّل سكربت الأرشيف الذي يكتب على الإنتاج.
- نجحت 31 حالة اختبار، واختبار المتصفح للممرضة والطبيب والملفات والشكاوى والتنبيهات.

## صفحة الإدارة
الرابط المحلي: http://127.0.0.1:4173/admin.html#admin. بعد دخول الدكتور ينتقل تلقائيًا إلى الصفحة. تُستعاد جلسة الإدارة بعد تحديث الصفحة، والخروج يعيد المستخدم إلى واجهة المرضى. السكرتارية والممرضة لا تملكان صلاحيات الإدارة.
تجمع الصفحة الحجوزات والطابور لكل الفروع، ملفات الحالات والشكاوى والعلاج، المستخدمين، المواعيد، والإعدادات. يتاح تنزيل نسخة JSON من بيانات العيادة للطبيب فقط؛ النسخة لا تحتوي كلمات المرور. زر تنزيل البيانات ليس استعادة تلقائية للنسخة.
متابعة المريض برقم الهاتف فقط، دون أي رمز متابعة. أزيل توليد الرموز وإرسالها وحفظها من البيانات المحلية الحالية. النسخ الاحتياطية السابقة محفوظة كما كانت.

## التحكم في العيادة والموقع والمستخدمين
- تبويب «بيانات العيادة»: اسم الدكتور والتخصص واسم العيادة، أرقام الحجز والطوارئ، نبذة ونص أسفل الموقع، أسماء الفرعين وعناوينهما وهواتفهما. يمكن إفراغ النصوص أو الهواتف لإخفائها.
- تبويب «التصميم والصور»: الألوان، عرض الصفحة، حجم النص واستدارة البطاقات، إظهار صورة الخلفية، رفع شعار وصورة طبيب أو إزالتهما، واستعادة التصميم الأصلي. تُصغّر الصور في المتصفح وتُحفظ كصور PNG/JPEG/WebP فقط؛ لا يقبل النظام HTML أو SVG أو CSS حرًا.
- تبويب «المستخدمون»: إنشاء حسابات طبيب/سكرتارية/ممرضة/دور مخصص، تغيير الاسم الظاهر والدور والفرع ونطاق الحجوزات، تحديد صلاحيات العرض والإضافة والتعديل والحذف لكل جزء، وتفعيل أو إيقاف الحساب، وتغيير كلمة السر لنفس الحساب، أو حذفه. اسم الدخول ثابت، والاسم الظاهر قابل للتعديل. آخر حساب طبيب فعال والحساب الجاري استخدامه محميان من الحذف الذي يغلق الإدارة.
- الطبيب يملك كل الصلاحيات دائمًا. المستخدم المخصص يبدأ بلا صلاحيات. السكرتارية والممرضة تحتفظان بصلاحياتهما الافتراضية ما لم يغيرها الطبيب. صلاحية إدارة المستخدمين تتيح منح الصلاحيات للآخرين؛ صلاحية تنزيل البيانات تشمل كل بيانات العيادة، ومنها الملاحظات الخاصة. نطاق الفرع يخص الحجوزات؛ صلاحيات الملفات والحالات مستقلة.
- تبويب «الحالات»: إضافة حالة دون حجز، تعديل الاسم والهاتف مع تحديث حجوزاتها وملفها والشكاوى المرتبطة، وحذف الحالة وكل تاريخها بعد تأكيد واضح. الملاحظات والشكاوى لها صلاحيات مستقلة.
- تبويب «الإعدادات والبيانات»: تغيير متوسط الكشف، تنزيل نسخة بيانات، حذف التجريبي فقط، أو حذف كل الحجوزات والمرضى والملاحظات والشكاوى. لا يحذف هذا الإجراء الحسابات أو تصميم العيادة وإعداداتها، وتظل عدادات أرقام الدور محفوظة لتجنب إعادة استخدام رقم قديم.
- الصلاحيات تفحص داخل الخدمة في كل طلب وتحديث، وتنعكس على التبويبات والأزرار الظاهرة. تغيير كلمة السر محليًا يبطل جلسات الحساب القديمة، وإيقاف المستخدم يمنع طلباته حتى مع جلسة مفتوحة.
- تحققنا من 31 حالة اختبار، ومن المتصفح: تحرير بيانات العيادة ونشرها، الألوان ورفع الصورة، إنشاء مستخدم وصلاحياته وسحبها، إضافة حجز وتعديل وحذف حالة، واستمرار وظائف الممرضة والتنبيهات والمتابعة بالهاتف. اختبار كلمة السر والإيقاف تم ضد الخدمة المحلية الفعلية. إعدادات التصميم الأصلية أُعيدت بعد الاختبار، ولم تُمس بيانات الإنتاج.
