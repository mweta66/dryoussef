# عيادة د. يوسف — Supabase

التصميم والوظائف الحالية محفوظة. التطبيق يستخدم Supabase Auth وقاعدة Postgres وخدمة Edge API. لا يوجد اعتماد على المنصة السابقة في النسخة المحوّلة.

## المشروع الحي

المشروع المطلوب هو `matkxrnobjdewhptybpj` داخل مؤسسة DrYoussefClinic، بحساب mweta66.

تم تطبيق مخطط القاعدة ونشر خدمة `clinic-api` على المشروع، وضبط `public/config.js` بالمفتاح العام فقط. مفتاح الخدمة السري يبقى داخل إعدادات Supabase ولا يوضع في الموقع. واجهة الموقع منشورة على https://dryoussef.vercel.app بحساب mweta66. يفتح START-CLINIC.cmd النسخة الحية مباشرة.

تمنع الجداول والدوال الوصول المباشر من المتصفح، وتتحقق الخدمة من جلسة Auth ومن الدور والصلاحيات الحديثة عند كل طلب. تحديث البيانات يستخدم مقارنة رقم النسخة داخل Postgres لتجنب فقد التحديثات المتزامنة. المتابعة العامة تعرض الدور فقط وتخضع لتحديد معدل الطلبات.

لن تُنقل بيانات التجربة المحلية إلى الإنتاج. أداة نقل البيانات تقرأ نسخة التصدير المحفوظة، ولا تستبدل بيانات مشروع قائم. تنشئ حسابات الموظفين بأسماء الدخول نفسها ومعرّفات Supabase جديدة وكلمات مرور أولية جديدة محفوظة في `.private/production-accounts.json` فقط؛ لا يمكن نقل كلمات مرور الحسابات القديمة كنصوص قابلة للقراءة.

## التجربة المحلية

شغّل `START-DEMO.cmd`، أو `npm run demo:seed` ثم `npm run demo` من مجلد العيادة. ملفات `.demo` تجريبية محلية ولا تدخل في النشر. `npm run demo:seed` يعيد تهيئة البيانات التجريبية؛ لا تستخدمه للحفاظ على تعديلات تجربة قائمة.

## التحقق

نجحت فحوص المنطق والصلاحيات والإدارة الـ31، واختبار واجهة الإدارة من المتصفح على خادم تجربة فعلي. جرى اختبار مخطط Postgres بما يشمل رفض الوصول العام، رفض رقم النسخة القديم، تحديد المعدل، وتحقق الجلسات وإبطالها. نجح الاختبار على Supabase الحقيقي للحسابات الثلاثة: تسجيل الدخول، إدارة الطبيب، رفض إدارة المستخدمين للموظفين، منع القراءة المباشرة من المتصفح، وإبطال الجلسات بعد تسجيل الخروج.

الواجهة ملفات ثابتة يمكن استضافتها على Vercel أو خدمة استضافة ثابتة أخرى، بينما Auth والبيانات والخدمة تعمل على Supabase.
