# عيادة د. يوسف — Supabase

التصميم والوظائف الحالية محفوظة. التطبيق يستخدم Supabase Auth وقاعدة Postgres وخدمة Edge API. لا يوجد اعتماد على المنصة السابقة في النسخة المحوّلة.

## المشروع الحي

المشروع المطلوب هو `matkxrnobjdewhptybpj` داخل مؤسسة DrYoussefClinic، بحساب mweta66.

تم تطبيق مخطط القاعدة ونشر خدمة `clinic-api` على المشروع، وضبط `public/config.js` بالمفتاح العام فقط. مفتاح الخدمة السري يبقى داخل إعدادات Supabase ولا يوضع في الموقع. واجهة الموقع منشورة على https://dryoussef.vercel.app بحساب mweta66. يفتح START-CLINIC.cmd النسخة الحية مباشرة.

تمنع الجداول والدوال الوصول المباشر من المتصفح، وتتحقق الخدمة من جلسة Auth ومن الدور والصلاحيات الحديثة عند كل طلب. تحديث البيانات يستخدم مقارنة رقم النسخة داخل Postgres لتجنب فقد التحديثات المتزامنة. المتابعة العامة تعرض الدور فقط وتخضع لتحديد معدل الطلبات.

لن تُنقل بيانات التجربة المحلية إلى الإنتاج. أداة نقل البيانات تقرأ نسخة التصدير المحفوظة، ولا تستبدل بيانات مشروع قائم. تنشئ حسابات الموظفين بأسماء الدخول نفسها ومعرّفات Supabase جديدة وكلمات مرور أولية جديدة محفوظة في `.private/production-accounts.json` فقط؛ لا يمكن نقل كلمات مرور الحسابات القديمة كنصوص قابلة للقراءة.

## التجربة المحلية

شغّل `START-DEMO.cmd`، أو `npm run demo:seed` ثم `npm run demo` من مجلد العيادة. ملفات `.demo` تجريبية محلية ولا تدخل في النشر. `npm run demo:seed` يعيد تهيئة البيانات التجريبية؛ لا تستخدمه للحفاظ على تعديلات تجربة قائمة.

## التحقق

نجح 61 فحصًا للمنطق والصلاحيات والتوقيت والجلسات والتقارير والمتابعة والقراءات المتزامنة، مع فحص لوحة المدير والطبيب والسكرتارية في المتصفح المحلي وعلى الموقع المنشور. شملت الفحوص رفض إدارة الموقع من حساب الطبيب، استعلام يوم سابق، واستمرار حجز السكرتارية بعد إنهاء الجلسة. حسابات وملفات الفحص المؤقتة تُحذف بعد الاختبار دون تعديل بيانات المرضى الفعلية.

## شاشة الدور والمتابعات

افتح `display.html?branch=dmn` أو `display.html?branch=alex` على تلفزيون العيادة، ثم اختر ملء الشاشة. الشاشة عامة وتعرض الأرقام فقط، ولا تعرض أسماء أو هواتف أو ملاحظات. الإيقاف المؤقت أو إنهاء الجلسة يوقف نداء الحالة الحالية. عند انقطاع الاتصال تُعرض رسالة واضحة وتُخفى الأرقام القديمة بعد دقيقة.

للدكتور والسكرتارية تبويب مواعيد المتابعة: اليوم والمتأخرة وخلال أسبوع والكل. سجّل موعد المتابعة في الملف الطبي، ثم سجّل نتيجة التواصل من القائمة. رابط واتساب لا يظهر قبل تسجيل موافقة المريض، ويفتح رسالة جاهزة يرسلها الموظف بنفسه؛ لا توجد رسائل تلقائية. تُطبّق صلاحيات الفرع على القائمة والتعديلات في الخادم.

## الأداء والتحديث الفوري

تجمع لوحة الطاقم بيانات التبويب في طلب واحد، وتعيد طلب التبويب الصحيح إذا تغيّر الاختيار أثناء بطء الاتصال. تستخدم الواجهة بروتوكول Supabase Realtime v1 لإشعارات تغيّر رقم النسخة فقط؛ لا تُنشر بيانات طبية أو معرّفات مرضى في القناة. تُقرأ البيانات بعد الإشعار من الخدمة المصرح بها، مع تحديث احتياطي كل دقيقة وشاشة التلفزيون كل نصف دقيقة. بيانات الموقع العامة تُحفظ مؤقتًا في المتصفح وتُحدّث عند الإشعار.

تستخدم القراءات جداول منفصلة مفهرسة للحجوزات والمرضى والملفات والشكاوى والأدوار. يحتفظ الإصدار بسجل الحالة ومقارنة النسخة كمسار كتابة متوافق؛ يُحدّث الإسقاط داخل المعاملة نفسها، ولا يمثل هذا إزالة جميع احتمالات تنازع الكتابة من التصميم القديم. لا تكتب إلى جداول الإسقاط مباشرة. في التثبيت الجديد، طبّق `supabase/schema.sql` ثم ملفات `supabase/migrations` بالترتيب قبل نشر الخدمة.

تعتمد حماية استعلام الهاتف على حصة لكل رقم وشبكة، وحصة إجمالية للشبكة، وحد لعدد الهواتف المختلفة؛ تُخزّن مفاتيح مجزأة لا الهواتف أو عناوين الإنترنت الخام في جداول الحماية. بذلك يمكن لعدة مرضى على Wi-Fi العيادة متابعة الدور دون استهلاك حد المريض نفسه.

## النسخ الآلي وتشخيص الاتصال

تأخذ قاعدة البيانات نسخة يومية الساعة 01:00 UTC وتحتفظ بـ14 يومًا داخل المشروع، مع نسخة أولى عند التهيئة. يستطيع المدير من تبويب الاتصال والنسخ الاحتياطي تنزيل آخر نسخة أو نسخة حالية خارجية. النسخ تضم بيانات العيادة والأدوار؛ لا تضم كلمات مرور Supabase Auth، ولا تغني النسخة داخل المشروع عن الاحتفاظ بنسخة خارجية آمنة. جرى اختبار الاستعادة في جداول مؤقتة والتحقق من الملفات والأدوار والتذاكر ثم التراجع دون استبدال بيانات التشغيل.

تتضمن استجابات الخدمة معرّف طلب، وتُسجّل المدة والعملية والحالة دون محتوى المدخلات أو البيانات الطبية. تظهر أخطاء 5xx الأخيرة للمدير مع تنبيه عند تكررها خلال عشر دقائق. تُحذف سجلات التشخيص الأقدم من 14 يومًا. سيناريوهات فحص قاعدة البيانات اليدوية موجودة في `tests/sql` وتعمل داخل معاملات متراجعة.

التحصيل والإيصالات غير مضافة إلى الموقع؛ ملف Excel المالي المستقل يُسلَّم خارج ملفات نشر الواجهة، ولا يُرفع مع بيانات المرضى إلى المستودع.

## المدير والعمل الطبي

دور `admin` يدير المستخدمين والصلاحيات والمواعيد وبيانات العيادة والتصميم والنسخ الاحتياطية والحذف الشامل وسجل العمليات. الطبيب يملك صلاحيات الحجوزات والمرضى والشكاوى والملاحظات في الفرعين، والتحكم في جلسة الكشف ومتوسط المدة والتقارير. لا يستطيع الطبيب إدارة النظام حتى إذا احتوت بيانات حسابه القديمة على صلاحيات إدارية. حذف ملف المريض بالكامل مخصص للإدارة، ويمكن للطبيب حذف حجز واسترجاعه من تبويب الحجوزات المحذوفة برقم تذكرة جديد.

لكل يوم وفرع جلسة مستقلة: بدء، إيقاف مؤقت، استئناف، وإنهاء. الإنهاء يعتبر الكشف الحالي منتهيًا ويوقف الانتقال التلقائي للحالة التالية، مع حفظ الانتظار واستمرار حجز السكرتارية. الطوارئ المحجوزة قبل بدء الطبيب تبقى منتظرة. الاستعلام العام يقبل رقم الهاتف وتاريخ الحجز دون عرض الاسم أو الملاحظات الطبية.

من تبويب التقارير يحدد الطبيب أو المدير الفترة والفرع، مع خيار إدراج الملخص الطبي والشكاوى. يفتح التقرير العربي الملون في نافذة مستقلة، وزر الطباعة يتيح اختيار «حفظ بتنسيق PDF». التقرير لا يحتوي بيانات حسابات الطاقم أو كلمات المرور. تُسجل العمليات الناجحة في سجل خاص بالمدير، دون كلمات السر أو محتوى الملاحظات الطبية.

الواجهة ملفات ثابتة يمكن استضافتها على Vercel أو خدمة استضافة ثابتة أخرى، بينما Auth والبيانات والخدمة تعمل على Supabase.

## الطابور والطوارئ والتوقيت المتوقع

توجد حالة واحدة جاري الكشف لكل فرع ويوم. تظهر أولًا، ثم الطوارئ المنتظرة، ثم بقية الانتظار حسب رقم الدور، ثم الحالات المنتهية. الطوارئ لا تقاطع الحالة الحالية، وتدخل بعدها وقبل الانتظار العادي. إنهاء الحالة الحالية يبدأ التالية تلقائيًا. أرقام التذاكر لا تتغير.

يبدأ التوقيت المتوقع عند بدء أول كشف، ويستخدم متوسط الكشف الذي يحدده الطبيب (15 دقيقة افتراضيًا). يستخدم الوقت المتبقي للحالة الحالية وعدد المنتظرين قبل المريض، ويتحدث بعد الإنهاء المبكر. التوقيت تقريبي وليس موعدًا مضمونًا.

## تغيير بيانات الدخول

الاسم الظاهر منفصل عن اسم الدخول. استخدم زر اسم الدخول وكلمة السر لتغيير بيانات الدخول الفعلية؛ تتم مزامنة الاسم مع Supabase Auth وإبطال الجلسات القديمة. لا تتغير معرّفات الحسابات أو صلاحياتها.

بيانات المرضى المستوردة ونسخها الاحتياطية خاصة ولا تدخل في المستودع أو نشر الواجهة.
