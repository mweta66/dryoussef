# Queue display controls and audio

Open **تجهيز شاشة الدور** from the queue or screen settings in administration. It requests a separate window and transfers the current staff session into that window's session storage before detaching the opener. Credentials never enter the URL or local storage. The settings button requires a live staff role with `display.manage` or `queue.configure`; anonymous displays and patient mode keep controls hidden. Expiring setup sessions refresh independently.

Inside **إعدادات الشاشة**, choose a branch, sound and date. The date selector offers shared administrator settings, automatic Cairo-day rollover, or a fixed date for this screen. **عرض تاريخ اليوم** switches this window to automatic today without changing the selected branch or the date on other screens. The URL preserves the local date mode and fixed date across reloads and settings polling. Returning to shared settings reapplies the administrator's date. Historical and future views are labelled as recorded bookings and never announce patients as entering now. Branch/date switches discard stale responses and reset audio announcement history.

The screen fills the viewport. The current ticket is larger than the next ticket. Fullscreen toggles entry/exit. Staff can hide all controls using patient mode.

The emergency-priority notice appears in a bordered box beside the branch name above the queue, instead of the footer. Its existing administrator text and visibility setting still apply. The setup panel opens as a scrollable dialog with close and patient-mode actions, so expanded controls do not squeeze the current/next ticket cards or become inaccessible on short mobile screens. Authorized branch links also open the authenticated setup window; the explicitly labelled patient display link remains a public view.

Administrators and accounts with `display.manage` can edit the notice from either the administration screen settings or **تصميم برواز رسالة الطوارئ** inside the separate screen window. Both editors use the same text, font size and color, background, maximum width, border thickness, corner radius, padding, alignment, and neon enable/color/intensity fields, with a preview before saving. Saving applies to all screens and uses the existing display revision to reject stale changes. Clinic introduction/header styling remains independent. `queue.configure` alone permits local screen/date/audio controls but does not grant shared notice editing.

The original clear notification is a mono PCM WAV, 44.1 kHz, 2.7 seconds: two ascending three-note phrases with attack/release envelopes and peak below full scale. Default notification volume is 85%; music remains 18%. Existing saved preferences are preserved. A user click enables audio; new active numbers ring once, duck background music, then restore it. Reload, date/branch switch and historical views remain silent.

After the user enables audio, changing to another tab does not pause music or announcements. Queue polling continues in the background while audio is enabled; silent hidden screens avoid unnecessary polling. Manual Stop still pauses playback. Unloading/navigating away from the screen suspends audio, and returning from the browser's back-forward cache can resume it. Browsers and mobile operating systems may throttle or suspend background tabs; closing the window cannot preserve its audio.

Validation: 212 passing unit tests and real-browser checks for popup opening, detached opener, authenticated settings, Today overriding a shared fixed date, local-date persistence, restoring shared settings, session refresh, and controls remaining hidden for patients and anonymous visits. Both notice editors were tested through save and reload, and native audio playback/time advancement and queue polling were verified while the document was hidden. The notice remained framed beside the branch at four viewport widths; settings were checked on short mobile viewports. Local checks use isolated synthetic data and do not alter live clinic records.
