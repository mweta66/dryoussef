# مراجعة العيادة وإصلاح شاشة الدور — ٣ نوفمبر ٢٠٢٦

الإصدار الجاهز: **2026.11.03.1**. آخر إصدار أكد المستخدم تشغيله على الواجهة والخدمة هو **2026.11.01.3**. الإصلاحات التالية لم تُنشر على الإنتاج حتى كتابة هذا التقرير؛ تحتاج تحديث الخدمة ثم الواجهة. لا يوجد SQL جديد لهذا الإصدار.

## الأعطال والإصلاحات

| المشكلة المعاد إنتاجها | الإصلاح والتحقق |
| --- | --- |
| نافذتان لشاشة الدور على نفس الفرع تتقاسمان حد الطلبات، فيتعطل التحديث مؤقتًا | تعريف مستقل لكل نافذة مع بقاء حدود IP والقراءة ومنع إساءة الاستخدام. اختبار فعلي بشاشتين مع الطبيب ثم الأدمن: بدء الجلسة، إنهاء الحالة، حفظ الكشف وفتح التالية، إيقاف واستئناف وإنهاء وإعادة بدء الجلسة؛ أرقام التذاكر ثابتة ولا ردود 429 في الاختبار النهائي. هذا سبب أمكن إعادة إنتاجه، وليس إثباتًا لسبب العطل على الإنتاج دون سجلاته. |
| إشعار التحديث يصل أثناء طلب شاشة الدور، أو رد قديم يصل بعد تغيير الفرع/التاريخ | الاحتفاظ بطلب تحديث تالٍ، منع تداخل القراءات، تجاهل الرد القديم، واحترام مهلة إعادة المحاولة عند 429 وفشل النقل. |
| حفظ مسودة طبية قديمة بعد مسودة أحدث، أو إعادة إنشاء مسودة بعد إنهاء الكشف | تسلسل الحفظ وحماية الحساب والحالة والفرع، انتظار الحفظ المعلق قبل حذف المسودة، ورسائل حفظ تعكس النص الحالي. الملف الطبي لا يتغير بمجرد حفظ المسودة. |
| دمج الحالات يترك الزيارات والخطط والطلبات الحديثة مرتبطة بالملف المحذوف | نقل الرسم المرتبط والهوية المستقرة، معاينة تشمل السجلات الحديثة، منع التعارض والتراجع بعد تعديل أحدث، حماية الأرشيف والدمج القديم، ومنع نقل بيانات فرع آخر بواسطة مفوض محدود. |
| تنظيف البيانات القديمة أو دفعة التدريب يترك سجلات معلقة | استخدام حذف مترابط مع حماية العمل اليدوي والدفعات الأخرى والحالات المشتركة، والحفاظ على التذاكر والاستعادة والأصول. |
| فحص استعادة يقبل هويات داخلية غير صالحة، أو يرفض حالات قديمة صحيحة بلا هوية صريحة | توحيد التحقق مع هوية الحالة الفعلية. تجربة قرص وتشفير وأجزاء وPNG وPDF نشط ومؤرشف واستعادة تشغيلية، مع رفض التلف والنقص. |
| نتيجة فحص الاستعادة تظهر في موضع قسم آخر، والتصدير القديم يوصف بأنه كامل | عرض النتيجة في قسمها، وتسميات تميز تصدير البيانات الأساسية عن نسخة الاستعادة التي تضم التاريخ والأرشيف والأصول. |
| حجز الزيارة القادمة يعرض undefined أو تاريخًا فارغًا | ترك إدارة الفرع للنموذج الجديد وعدم إنشاء تنبيه الحجز القديم دون فرع وتاريخ صالحين. |

## نتائج الاختبارات

- الحزمة النهائية: **531 اختبارًا آليًا ناجحًا، صفر فشل، صفر تخطٍ**؛ بناء الخدمة والواجهة وفحص 265 ملف JavaScript وحزمة Vercel نجحت.
- **59 تحققًا على PostgreSQL17.6 معزول**: إعادة الترحيلات، الصلاحيات، الإسقاط، إيصالات الحفظ وضياع الرد، حذف واستعادة، وقراءة السكرتارية وسحبها.
- الحزمة النهائية بالمتصفح: **8 تحققات بشاشتين مع الطبيب و8 مع الأدمن**؛ **6 تحققات دمج واستعادة**. النماذج الداخلية المخفية للدمج تُفتح باستدعاء اختباري، ثم تُستخدم أزرارها الفعلية؛ لا ادعاء بوجود مدخل تنقل ظاهر لها.
- **19 تحقق استعادة على القرص** شمل التشفير والأجزاء وأصول الصور وPDF المؤرشف وإعادة القراءة والصلاحيات.
- خلال المراجعة الأوسع: **147 سيناريو وظيفيًا**، **107 تنقلات** للحسابات الثمانية، **680 فحص مقاسات** بأربعة عروض ووضعين، و24 تحققًا من تحميل خط Cairo فعليًا. **85 تفعيل أداة/إلغاء تأكيد** محسوبة منفصلة عن التنفيذ الفعلي، و16 فحص رابط اتصال دون إجراء اتصال أو إرسال رسالة.

الأدلة النهائية الملخصة في [verification.json](qa-final-2026-11-03/verification.json)، ومعها نتائج شاشة الدور للطبيب والأدمن والدمج والاستعادة وPostgreSQL. سكربتات إعادة الاختبار محفوظة في scripts/qa؛ تستخدم prepare.cjs وجذورًا مؤقتة منفصلة وحسابات مولدة فقط.

## حدود الاعتماد والنشر

كل العمليات المدمرة تمت على بيانات مولدة معزولة. لم تُحذف أو تُعدّل بيانات مرضى الإنتاج. لا تتيح الجلسة اتصال الإنتاج أو بيانات اعتماد نشره؛ لا يُعتبر نجاح الاختبارات إثباتًا لنشر الإصلاح.

اختبارات المقاسات تعمل على Chromium، ولا تثبت اختبار Safari الحقيقي على الآيفون أو Firefox أو Edge. لا تعني الأعداد اختبار كل قيمة ممكنة لكل زر أو كل ترتيب تزامن. لا تشمل نسخ الاستعادة كلمات مرور وجلسات Supabase Auth وأسرار الاستضافة. لا يزال التخزين الأصلي JSON والموبايل الأساسي فريدًا؛ هذه حدود قائمة وليست ادعاءً بإزالة كل حدود التوسع.

بعد نشر الخدمة والتحقق من إصدارها، تُنشر الواجهة المطابقة ثم تُختبر رحلة حجز تجريبية وفتح شاشة الدور على المشروع الحقيقي، مع الأدمن والسكرتارية، دون عمليات حذف على بيانات حقيقية.
