# Configurable clinic, design and Quran display

The branch registry is data managed by clinic administrators, not a two-branch constant. Existing dmn/alex IDs remain for compatibility. Administrators can add and edit branches and archive referenced branches; unreferenced empty branches can be deleted. At least one branch stays active. A running/paused examination must end before archiving. Patient records and assigned accounts retain their original branch ID. All booking, role, report, import, public queue and projection validation uses configured branches.

Schedules support flexible availability, multiple non-overlapping intervals per weekday and dated exceptions/closures. Public schedules are informational; patient estimates still start with the actual doctor examination, not scheduled hours. The doctor remains one person and cannot examine in two branches simultaneously. Booking in another branch remains allowed, with an explicit warning. New booking defaults follow the chosen doctor branch rather than a hardcoded default. The waiting screen follows the doctor branch automatically for today; manually selecting a branch disables following until the user re-enables it. Historical date selections remain silent records.

Design controls include ten paired light/dark themes, per-mode colors, header height/logo/photo sizes, multiline header text, larger multiline patient introduction, preview and previous-design restore. Text uses textContent/escaped values; Enter is preserved without allowing HTML. Image conversion in progress blocks saving; saved settings are re-read without stale cache. Existing personal light/dark choices remain honored. Preset text/button/header contrast is tested at 4.5:1 or above.

Quran audio is hosted separately in public audio-only storage; clinical records remain private. The 114-item manifest loads without downloading recordings until sound is enabled. The selected recording plays, then the playlist advances and wraps. Most supplied files remain unchanged; Al-Baqarah was re-encoded in full at 48kbps mono to fit the current per-file storage limit. Audio never plays on patient or staff pages. The old background music and musical notification are not requested.

Queue changes are announced in Arabic with the current ticket number only. Initial load, historical dates, refreshes and branch switches do not announce stale numbers. The Quran level ducks during speech and restores on completion or error. Speech is cancelled on hiding the page, pause or selection changes. A test-call button and Arabic voice picker are available. The default is bundled recorded Arabic calls, independent of installed system voices. Full calls cover tickets 1–100; prerecorded Arabic number components cover larger values. Optional installed Arabic voices remain available. Only general numbers/phrases were used to prepare the recordings; patient data is never sent to a speech service. Runtime recordings are served locally with the app. Automated checks cover recorded Web Audio playback and mocked optional system speech, while Quran playback uses the native media element.

Synthetic reset is a separate operator procedure. The user explicitly classified the previous imported 100 patients as synthetic and authorized deletion. Only their approved phones/IDs and identified demo records are purged; accounts, settings and unclassified records remain. New records are clearly marked synthetic, respect configured branch schedules, and preserve at most one active examination. A backup within the existing database is taken first. Private source lists and service credentials are never included in Git or deployment assets.

Validation includes unit tests for dynamic branches, cross-branch permissions, third-branch queue/report/lookup, schedule intervals, archival safety, design fields, theme contrast, classified demo reset and Arabic voice selection. Browser acceptance covers branch creation/scheduling/deletion, doctor presence and TV auto/manual behavior, header text/newlines/theme/image readback, native Quran playback and playlist/ducking with mocked speech, and all content fitting 11 viewport sizes.

Release validation: 114 unit tests passed, plus browser acceptance for dynamic branches, paired themes, saved doctor/logo images, multiline text, automatic doctor following, manual/historical selection, native recorded Arabic speech, and 11 viewport sizes. The classified production reset removed 97 remaining bookings and 100 patient records from the approved synthetic group, created 100 marked synthetic cases and preserved six unclassified bookings as well as all accounts/settings. A private backup within the database preceded replacement.

The full 114-chapter audio library was published and byte-range verified. Total audio storage is 804,209,235 bytes. Production frontend carries only the manifest and small local Arabic call recordings, not the full Quran files.
