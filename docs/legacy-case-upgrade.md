# تحديث بيانات الحالات القديمة على الموقع الحي

الموقع `https://dryoussef.vercel.app` يقرأ قاعدة Supabase عبر خدمة `clinic-api` في المشروع `matkxrnobjdewhptybpj`. تحديث `fixtures/clinic-demo.json` أو نشر واجهة Vercel وحدهما لا يعدلان بيانات القاعدة الحية أو كود خدمة Supabase.

## النشر

بعد دمج التعديل، انشر الواجهة وخدمة Edge معًا. من جلسة موثقة لها صلاحية نشر المشروع:

```sh
npx supabase functions deploy clinic-api --project-ref matkxrnobjdewhptybpj
```

حقول الزوج محفوظة في سجل المريضة داخل JSON الحالي؛ لا يتطلب هذا الإصلاح إعادة إنشاء القاعدة أو إعادة تهيئة الحالات. لا تستخدم seed أو provisioning لتحديث عيادة قائمة.

افتح `admin.html#admin` بحساب الأدمن بعد النشر. قبل إظهار مساحة العمل يكتمل تحديث الحالات القديمة مرة واحدة عند غياب `demoProfileVersion=1`. ويمكن إعادة المحاولة من الإعدادات بزر «تحديث بيانات الحالات الافتراضية القديمة». يتحقق العميل من إصدار الاستجابة؛ ظهور رسالة تطلب تحديث الخدمة يعني أن نشر الواجهة سبق نشر `clinic-api`.

## ما يغيره التحديث

- ينشئ سجلات الحالة الناقصة الموجودة في الحجوزات فقط، ويستكمل حقول الزوج المفقودة للحالات الافتراضية المعروفة.
- يستبدل الأسماء الوصفية مثل «حالة اصطناعية» بأسماء نساء مصرية مولّدة.
- يستبدل النصوص الافتراضية القديمة المطابقة تمامًا لقوالب التوليد في الملاحظات والشكاوى والملف الطبي. يحتفظ بالنص الحر المدخل بواسطة المستخدم، وأسماء الأزواج وبياناتهم الموجودة، والحقول التي مسحها المستخدم صراحة.
- يحافظ على الهاتف الأساسي، وأرقام وتواريخ الحجوزات، والحالة الجاري كشفها، وأرقام وتوقيتات الشكاوى. لا يضيف نسخة مكررة من الحالات.
- يسجل التغييرات في سجل النشاط، ويحدث نسخة الملف الطبي لتجنب حفظ نسخة مفتوحة قديمة فوق التصحيح.

الأسماء والبيانات المولّدة أمثلة وليست سجلات أشخاص فعليين. تحتفظ ملفات المصدر بوصفها الافتراضي خارج شاشات المرضى.

## التحقق

تغطي الاختبارات قاعدة قديمة تحمل أعلام تحديث الأسماء والزوج السابقة، مع حالة موجودة في الحجوزات دون سجل مرضى، وملفات تحتوي النصوص القديمة، وبيانات كتبها المستخدم يجب حفظها. وتجربة المتصفح تتحقق من ظهور بيانات الزوج والمحتوى المصحح عند الطبيب بعد تحديث الأدمن وإعادة تحميل الصفحات.

لم يتم التحقق من النشر الحي في هذه البيئة؛ الوصول إلى نطاقي Vercel وSupabase يعيد رفض اتصال، ولا توجد بيانات اعتماد نشر Supabase متاحة. نجاح الاختبارات المحلية ورفع Git لا يثبتان تطبيق التحديث على القاعدة الحية.

## أدوات شاشة الدور وسجل العمليات

شاشة `display.html` العامة تخفي أدوات الفرع والتاريخ والصوت وزر الإعدادات منذ أول تحميل. من حساب الأدمن أو من مُنح صلاحية تجهيز الشاشة، استخدم زر «تجهيز شاشة الدور» من مساحة العمل. يفتح الرابط في نفس التبويب للحفاظ على الجلسة، وتتحقق الشاشة من الدور الحالي بالخادم قبل إظهار زر الإعدادات. اختر «عرض للمرضى وإخفاء الإعدادات» بعد التجهيز؛ يظل العرض نظيفًا حتى عند إعادة تحميل الصفحة. تغيير الرابط إلى `settings=1` وحده لا يمنح صلاحية.

تفاصيل سجل العمليات أصبحت بطاقات عربية توضح الحالة أو الحجز والحقل والقيمة قبل وبعد، مع البحث وتقسيم العمليات الكبيرة إلى صفحات وإخفاء المراجع التقنية والتحديثات الآلية افتراضيًا. نشر خدمة Edge يحفظ هوية الحالة ورقم الحجز وقت العملية لظهورهما حتى بعد الحذف. لا تُعرض هذه المعلومات في قائمة السجل العامة لمن يملك عرض السجل فقط؛ تفاصيلها تتطلب `audit.details`.
