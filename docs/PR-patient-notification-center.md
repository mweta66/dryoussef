طلبات الحجز الجديد وتغيير الموعد والإلغاء كانت تظهر كعدد للطلبات المنتظرة فقط، ولا توجد حالة قراءة مستقلة لكل مستخدم. يضيف هذا التغيير مركز إشعارات داخل كل حساب من حسابات الطاقم، مع جرس وعدد غير المقروء، وقائمة حسب نوع الطلب وحالته، وتاريخ وفرع كل إشعار، وقراءة/إلغاء قراءة وتحديد الكل كمقروء.

- تحفظ حالة القراءة على السيرفر لكل مستخدم، وتستمر بعد إعادة التحميل والدخول من جهاز آخر. القراءة لا تعتمد الطلب ولا تغيّر الحجز. اعتماد الطلب أو رفضه يظهر كتحديث مستقل.
- يظل كل حساب داخل نطاق فروعه. الحساب الذي لا يملك `requests.read` يرى معلومات عامة دون اسم أو موبايل المريضة ودون زر فتح الطلب؛ لا تُمنح صلاحية الاعتماد تلقائيًا.
- تحديث عبر Realtime الحالي مع بديل كل 15 ثانية أثناء فتح الموقع، وتنبيه عند الدخول وعودة الاتصال. الصوت اختياري ومتوقف افتراضيًا. لا يوجد ربط مزود جديد أو Browser Push بعد غلق الموقع.
- التحديث الدوري في Supabase يقرأ أجزاء الأدوار والطلبات والإعدادات وحالة القراءة فقط، دون تحميل الملفات الطبية أو الحجوزات أو سجل العمليات. لا تضيف القراءة سجلات عمليات طبية فارغة.
- زر «عرض الطلب» يفتح قسم الطلبات ويحدد الطلب المطلوب، مع احترام النماذج غير المحفوظة. المركز يدعم الموبايل والوضع الداكن وEscape وعودة التركيز إلى الجرس.

التحقق: اختبارات Node وEdge لتدفقات الطلبات الثلاثة، العزل بين المستخدمين والفروع، سحب صلاحية التفاصيل، الترقيم والفلترة، منع فقد إشعار جديد أثناء «قراءة الكل»، الردود المتأخرة وتغيير الفلاتر، ومحدد البيانات في Supabase. تجربة متصفح محلية للسكرتارية والممرضة ومدخل البيانات: حفظ القراءة بعد Refresh، التنبيه الدوري، الفلاتر، فتح الطلب، الخروج، الموبايل والوضع الداكن.
