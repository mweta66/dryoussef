# المراجعة الموسعة للحسابات والإجراءات — ٤ نوفمبر ٢٠٢٦

**الواجهة الجاهزة:2026.11.04.5، متوافقة مع خدمة2026.11.04.4. لا يلزم SQL أو إعادة نشر Supabase لهذه الإصلاحات.**

استكملت هذه الجولة مراجعة الاستقبال السابقة بمسارات تغيير كلمة السر، ومسودات النماذج واستكمالها، والتقارير وبطاقات المواعيد، وتأخر الشبكة أثناء تسجيل الخروج أو تبديل الحساب. أُصلحت الأعطال التي أمكن إعادة إنتاجها وأُعيد اختبار المسارات المتأثرة. توجد أدلة لكل مجموعة اختبارات في المجلد المجاور؛ نتائج الجولة السابقة لا تُجمع مع الحالية باعتبارها سيناريوهات فريدة.

## الأعطال المثبتة والإصلاحات

| العطل المثبت على النسخة السابقة | التعديل والنتيجة |
| --- | --- |
| الملاحظات الطبية تُحفظ فعليًا، ثم يؤدي فشل حذف مسودتها الخاصة إلى إظهار خطأ بدل تأكيد حفظ الملف | أصبح تأكيد حفظ الملف مستقلًا عن تنظيف المسودة؛ فشل التنظيف يعطي تنبيهًا يوضح أن الملف محفوظ. حُظر تكرار الحفظ أثناء انتظار الرد، وحُفظ النص الأحدث المكتوب أثناء الطلب. تُرتّب إزالة المسودة مع عمليات حفظها حتى لا تمحو كتابة أحدث. اختُبر فشل التنظيف من الطبيب والأدمن. |
| رد سجل المريضة المتأخر يمكن أن يفتح نافذة بيانات خاصة بعد خروج السكرتيرة | تُرفض نتيجة أي طلب محمي تغيّرت جلسة صاحبه قبل إرسال الطلب أو وصول الرد، دون إعادة كتابة العملية. أضيف تحقق خاص بصاحب السجل ونطاقه ونافذته. اختُبرت استجابات السجل والمسودات وبيانات التواصل وتصدير التقارير بعد الخروج. |
| نافذة الملف الطبي غير المحفوظ قد تبقى معروضة بعد تسجيل الخروج إذا رُفض تأكيد إغلاقها | الخروج يزيل محتوى النوافذ الخاصة ومركز الإشعارات وسجل التفاصيل، ويفك تعطيل واجهة الصفحة. إعادة الإنتاج أظهرت AUTH وme فارغين مع استمرار ظهور نص طبي في النافذة؛ الاختبار بعد الإصلاح يمنع ذلك. |
| اكتمال التحديث التلقائي للألوان والصلاحيات بعد دخول الأدمن يعيد رسم الصفحة فوق نص بدأ الأدمن تحريره | لا تُعاد كتابة مساحة العمل إذا كان المستخدم يحرر نموذجًا أو توجد عملية نشطة. اختبار متعمد أخّر آخر ترقية، أدخل نصًا، ثم أطلق الرد القديم؛ النص يبقى ويُحفظ فعليًا. |

أُضيفت أيضًا حماية للنماذج: نتيجة حفظ متأخرة لا تغلق نموذجًا جديدًا ولا تعتبر مسودته محفوظة. واستكمال المسودات يرتبط بمعرّف المسودة الملتقط وقت الطلب، ويحترم الحساب والنطاق الحاليين، بدل الاعتماد على ترتيب قائمة قد يتغير أثناء القراءة. نُفّذ استكمال مسودة حجز لجميع الحسابات الثمانية، واستكمال مسودة نبذة العيادة للأدمن، مع تحقق أن المراجعة لا تنشر البيانات تلقائيًا.

## الحسابات والمسارات

| الحسابات | أمثلة على الإجراءات الفعلية المفحوصة |
| --- | --- |
| سكرتارية الإسكندرية ومطروح ودمنهور وليبيا | حجز ورفض التكرار، بيانات الأسرة، الحالات والحضور وإلغاؤه، رقم تذكرة ثابت، طلب مراجعة عاجلة، تأكيد التواصل والطلبات وتغيير الموعد وإلغاؤه، ملف للقراءة حسب الصلاحية، بطاقات المواعيد ومسودة الحجز وكلمة السر. رفض تعديل فرع آخر والبيانات والصلاحيات الإدارية غير الممنوحة. |
| الطبيب والأدمن | الكشف والملاحظات والمسودات والانتقال للتالية والجلسة، المتابعة، التقارير PDF وCSV، الحجز والتعديل والحذف والصور، وسائل الدفع. إجراءات الإدارة والتنظيف والاستعادة والأدوار والمظهر والإعدادات للأدمن ضمن المجموعة الإدارية. |
| الممرضة | الحجوزات والحالات والحضور، الشكاوى والمرفقات الأصلية وPDF، سجل المريضة دون ملاحظات الطبيب، إشعارات الطلبات وبطاقات المواعيد والمسودات وكلمة السر؛ رفض اعتماد الطلبات أو إدارة النظام دون منح صلاحية. |
| إدخال البيانات | إضافة وتعديل بيانات المريضة والحجز، البحث والتنقل بين الصفحات والمسودات والبطاقات وكلمة السر؛ رفض تغيير حالة الحجز أو الاطلاع على الملف الطبي أو إدارة الدفع والمستخدمين. |
| المريضة | طلب حجز ثم اعتماده، استعلام وقراءة تأكيد الموعد، طلب تغيير ثم اعتماده وطلب إلغاء ثم اعتماده؛ تظل المعاملة الأصلية كما هي قبل قرار السكرتارية ولا ينشأ حجز مكرر. |

التفاصيل الدقيقة في ملفات JSON. نطاق الصلاحيات هنا هو الإعداد الافتراضي وحالات المنح والسحب التي تغطيها الاختبارات، ولا يعني اختبار كل تركيب ممكن من مفاتيح التفويض المخصصة.

## النتائج النهائية

- **574 اختبارًا آليًا ناجحًا، صفر فشل وصفر تخطٍ**، تشمل التنفيذ الخادمي Node وEdge وتعاقد الإصدار وحزمة النشر، إضافة إلى حالات السباق الجديدة في المتصفح.
- **298 تحققًا وظيفيًا بالمتصفح**:90 للإجراءات الموسعة للحسابات الثمانية،90 لإجراءات الطاقم،58 للاستقبال وموثوقيته،18 لموثوقية الدفع،15 للإدارة،13 لطلبات المرضى واعتمادها،6 للمسودات الطبية،6 للدمج والاستعادة، وتحققان لعدم مسح نموذج الأدمن بعد التحديث التلقائي. بعض البنود تحققات عدم وجود أخطاء JavaScript، وليست أزرارًا فريدة.
- فحص **276 ملف JavaScript** وبناء الواجهة وحزمة Vercel نجحا. سكربتا QA الجديدان نُفذا فعليًا.
- المراجعة السابقة وثّقت أيضًا77 تحققًا على PostgreSQL و19 تحقق استعادة على القرص و107 تنقلات و696 فحص عرض. لا توجد تغييرات في سلوك الخدمة أو قاعدة البيانات في هذه الجولة تستدعي وصف تلك الفحوص كتشغيل جديد.

## النشر وحدود التحقق

التعديل الحالي في الواجهة. حزمة الخدمة المعاد توليدها تختلف في بيانات رقم الإصدار فقط. **يمكن إبقاء الخدمة المنشورة على2026.11.04.4**؛ عقد API والقدرات متطابقان، وقد تعرض شاشة التشخيص «متوافقتان، لكن إصدار النشر مختلف» مع الواجهة2026.11.04.5. لا توجد خطوات Supabase أو SQL إضافية مطلوبة.

كل الاختبارات على بيانات مولّدة وخادم معزول وChromium. اختبار كلمات السر استخدم محاكي الدخول المحلي؛ مشاركة الموعد استخدمت زر الواجهة مع بديل اختباري للحافظة. لم تُرسل رسائل أو تُجرَ مدفوعات فعلية. شبكة بيئة التنفيذ تحجب الموقع المنشور ولا توجد بيانات اعتماد مزود مهيأة، لذلك التحقق من حسابات الإنتاج وSupabase Auth وسجلاته، وSafari الفعلي على الآيفون، متبقٍ. نجاح الحزمة لا يثبت تجربة كل قيمة أو كل ترتيب تزامن ممكن.
