# Audit fixes — 17 October 2026

Credential updates now synchronize the login name and role before changing a password. A failed role write cannot change the password; name rollback failures and uncertain password write outcomes have explicit messages. Confirmed password saves return a warning if session revocation is unavailable, and administrators can retry revocation with a dedicated End sessions button. All operations recheck server-side permissions; normal permission denials no longer masquerade as expired authentication.

Temporary role-read failures retain authentication, clear privileged client state and retry verification with 5/10/20/30-second backoff. Invalid or disabled sessions still log out. Late verification replies cannot restore privileges after logout or a new sign-in. Only named read actions may retry once after transient errors; writes are never automatically retried by the browser.

Upstream errors now include request-scoped correlation IDs and sanitized operation/timeout diagnostics without passwords or patient content. Successful non-JSON upstream responses are rejected rather than treated as data. Historical 503 events were verified, but their original cause was not proven; these changes improve recovery and future diagnosis and do not guarantee the provider cannot fail.

The official local demo server now serves MP3/WAV MIME types and byte ranges, including suffix, HEAD and invalid-range behavior. Canonical URL, sitemap, robots exclusions and a restrictive camera/microphone/location Permissions-Policy were added. Existing inline event handlers still require the existing CSP inline allowance; replacing that system is a larger separate migration, not an untested policy toggle.

A database security check found public execution privileges on the internal rls_auto_enable event trigger. Its public/anon/authenticated privileges were revoked; ownership and automatic RLS behavior were preserved. The idempotent SQL is included as a migration. Rechecking advisors removed both related warnings. Leaked password protection is still an account-level warning; enabling a paid-plan-dependent feature was not assumed.

Backup checksum verification and restore rehearsal succeeded in temporary database tables with ROLLBACK, without touching original records. A separate local full medical backup export was rejected by automatic approval review because that destination needs explicit consent; it was not executed. The rehearsal does not restore Auth accounts or certify a full disaster-recovery process.

Validation: 96 passing unit tests and syntax checks; isolated browser verification of username/password change, old credential rejection, session revocation and recovery after a synthetic outage; role navigation for admin/doctor/both secretaries/nurse/custom; patient history and doctor presence; JSON/CSV/XLSX import and stale-preview rejection; official demo media MIME/range and native playback. Tests involving writes used synthetic local state. Production verification uses read-only API/browser checks, except the explicitly requested deployment and internal-function permission fix. No real users were renamed or had their passwords changed.
